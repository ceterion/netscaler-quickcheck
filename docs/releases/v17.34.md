# netscaler-quickcheck v17.34 (2026-10-27)

Whitelist with three rule forms, `--pin`, change times on web files. Rules stand 2026-10-27 unchanged. Everything else as in `v17.33.md`.

## New in v17.34

- **Whitelist, three rule forms:** directory (`.../` : everything below, never code), file (`...$` : exactly that file), pinned file (`...$@sha256=<hash>` : exactly that version, mandatory for `.js`, `.php`, `.pl`, `.sh`, `.cgi`, `.py`, `plugins.xml`). A directory rule no longer covers code files; a file rule on code without a pin is ineffective and warned about. The WARN of 17.33 for "no trailing `$`" was too broad and now fires only for rules ending with neither `/` nor `$`.
- **`--pin <path>`** prints ready pin lines for all code files below the path (current hash) and exits; append after reviewing.
- **Web files since boot:** the report lists every file that is not whitelisted, with its change time, newest first (terminal and report; `DETAIL_MAX` limits the display); from 20 files in one directory the non-code files are grouped per directory.
- **Mapping table:** `user`/`mail` entries shorter than 3 characters or equal to a report word are skipped when the table is loaded (the table itself stays unchanged); the anon header names them. Fixes 17.32 reports where an account `info` or `-` had already entered the table.
- README 15 "Howto Whitelist" rewritten as a five-step procedure; whitelist template rewritten.

## Update

Replace `ns_quickcheck.sh` in `/var/nssnapshot/`; the rules file is unchanged. Existing whitelists keep working; file rules on code need a pin from now on (`--pin`).
