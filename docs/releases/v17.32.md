# netscaler-quickcheck v17.32 (2026-10-27)

Self-hits removed, process crashes counted per event. Rules stand 2026-10-27. Everything else as in `v17.31.md`.

## New in v17.32

- **No more self-hits.** `nsprofmon_mgmt.pl` logs CPU snapshots including the command lines of running processes, among them the grep and perl calls of the quick check with their search patterns; every check on the syslog family could match its own pattern text and report it. These lines are now set aside when the syslog family is read and checked only against `SUSPECT_PROC_RE` (suspicious processes with a timestamp, a time series block 5 cannot provide). Identical lines from `ns.log` and `messages` count once. Block 4 therefore shows fewer hits than 17.31 on the same logs; nothing is missed, the self-hits are gone.
- **Process crashes as events.** Pitboss and kernel lines (`PITBOSS_RE`, `KERNEL_EXIT_RE`, rules stand 2026-10-27, formats verified in the lab) become one event per process and PID with signal, restart counter and `/var/core/<n>` directories in the window (also without a log line, after rotation). nsaaad is rated as before (yellow; red with SAML and an open SAML CVE), httpd yellow with a pointer to CTX697263, nsppe with DTLS errors red, other processes INFO. The old wide pattern survives as `NSAAAD_CRASH_LEGACY_RE`: a line that matches only there gives an INFO "unknown format, please send in".
- **Anonymized address lists and share file.** Each run now also writes `..._ips_anon.tsv` and `ns_quickcheck_observed_ips_anon.tsv` (no host name, remarks of the block and trusted lists removed, mapping table applied) and `..._share.tsv`: the cumulative list reduced to the reliable categories (`payload_download_host`, `injection_source`, `webshell_hit`, `outbound_hit`, `aaa_bruteforce`, `aaa_maschine`, `aaa_hit`, `ssh_bruteforce`, `dropper_requester` from 3 hits) with first/last seen, days, peak count and window, last count and whether the address is already in the rules file; no appliance identifier, no remarks. Operators can send the share file to ceterion after review; it feeds a planned corroborated address feed.
- New test log `pitboss-crash.log` (lab lines, self-hit lines, two processes), fixture `crash` (lines duplicated across `messages` and `ns.log`, old report with indicator strings inside the tree, expected: 2 events, no self-hit).

## Update

Replace `ns_quickcheck.sh` and `ns_quickcheck.rules` in `/var/nssnapshot/`. With an older rules file the script falls back to the old nsaaad pattern and says so.
