# netscaler-quickcheck v17.33 (2026-10-27)

Anonymizer, web-file classification and whitelist hash pins. Rules stand 2026-10-27 unchanged. Everything else as in `v17.32.md`.

## New in v17.33

- **Anonymizer:** account names shorter than 3 characters and reserved report words (`OK`, `INFO`, `WARN`, `GELB`, `ROT`, `ORANGE`, `TRUST`, `ACTION`, `RESULT`, `user`, `root` and others) are no longer added to the mapping table. Before, an account named `info` turned every `[INFO]` tag into `[userNNN]`, and an account named `-` replaced every hyphen; anonymized reports of 17.32 and earlier can show this.
- **Web files since boot:** the classification ("Ergebnis") is computed over all changed files, not over the 30 displayed; executable files (`.js`, `.pl`, `.sh`, `.cgi`, `.py`, `plugins.xml`) are never classed as a theme change and get their own hint "executable code, diff against the previous version".
- **Whitelist:** optional hash pin `webfile:<regex>@sha256=<hash>`: the file is whitelisted only with that hash, otherwise "whitelisted file changed again" (yellow). `webfile` rules without a trailing `$` get a WARN in the header (they cover everything below and every future change). The header says "Whitelist: nicht vorhanden" when the file is missing.
- Probing time span is chronological (was text-sorted: "2026-10-23 bis 2026-10-21").
- Regression fixture `aaa-dup`: AAA failures duplicated across `ns.log` and `messages` count once (12, not 24); the current `ns.log` is read. Brute-force findings of 17.31 that only crossed `AAA_BF_MIN` through double counting do not return; the halved numbers are the real ones.

Replace `ns_quickcheck.sh` in `/var/nssnapshot/`; the rules file is unchanged. Re-create anonymized reports that were produced with 17.32 or earlier if an account name collided with a report word.
