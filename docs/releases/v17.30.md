# netscaler-quickcheck v17.30 (2026-10-23)

CTX697263 (PHP2Shell) support, one day after v17.29. Rules stand 2026-10-23. Everything else as in `v17.29.md`.

## New in v17.30

CVE-2026-109618 and CVE-2026-109619 (PHP in the management portal, CVSS 4.0 9.2, CTX697263 of 2026-10-22):

- Block 1 rates both against the build: 14.1-73.41, 13.1-64.28, 14.1-FIPS 73.41, 13.1-FIPS 37.282 (condition `all`, the management portal always runs on the NSIP). `vuln63` in the result line.
- Block 2 shows the management addresses (NSIP, SNIPs with management access) and whether the DENY ACLs on ports 80/443 recommended by Citrix exist (`MGMT_ACL_RE`); yellow on a vulnerable build without ACL, INFO otherwise.
- Block 4b checks PHP memory and fatal patterns in the web server error log including `admin_ui` (`HTTPERR_PHP_ANOMALY_RE`), from `PHP_ANOMALY_MIN` lines (default 3): INFO on a fixed build, yellow on a vulnerable one.
- Block 5 turns it red when a new PHP file appeared in the same window on a vulnerable build.

This is a heuristic on error classes; no exploit signature has been published by Citrix or the PHP project. Existing checks are unchanged. New: test log `httperror-php.log`, fixture `php2shell`.

## Caveats

Citrix lists 13.1 "before 13.1-64.28" but also warns that NetScaler Console may flag 13.1-64.23 incorrectly; until the bulletin text settles this, 64.28 is the fix build in the rules. 13.1-NDcPP (fix 37.282) is rated as 13.1-FIPS. On appliances with large configurations the GUI produces the same PHP memory messages; that is why a fixed build only gets an INFO line.

## Update

Replace `ns_quickcheck.sh` and `ns_quickcheck.rules` in `/var/nssnapshot/`, mode 600; config, whitelist, block list, custom file and mapping table stay. Optional in `ns_quickcheck.conf`: `PHP_ANOMALY_MIN`.
