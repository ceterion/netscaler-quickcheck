# netscaler-quickcheck v18.5 (2026-11-05)

Status: gelaufen (Betreiber-Gateway 2026-11-05 13:52, Script 7861585d...)

Runtime of the anonymizer, account files internal by default, profiling with start and end times, bilingual config template. Rules stand 2026-11-05d unchanged.

## New in v18.5

- **Anonymizer, one pattern per class.** `anon_apply` compiled one regular expression per mapping entry and line (1,764 entries on a customer gateway times tens of thousands of lines in the account files: minutes at the end of every run). Now one alternation per class (addresses, hosts, accounts; longest first, same word boundaries) is compiled once and the match is looked up in a hash. Output is byte-identical (checked on six fixtures, mapping tables identical). `anon_add` runs batched in one awk pass instead of three processes per value.
- **Account files internal by default.** `_accounts.tsv`, `_logons.tsv` and `ns_quickcheck_observed_accounts.tsv` get no anonymized copy in the run (`ANON_ACCOUNTS=0`); the footer names the on-demand command `sh ns_quickcheck.sh --anon <file> > <file>_anon.tsv`, which uses the mapping table of the last full run. `ANON_ACCOUNTS=1` restores the copies.
- **Profiling with times.** `QC_PROFILE=1` prints `profile: <block> start HH:MM:SS ende HH:MM:SS dauer Ns` per block to stderr (blocks 0 to 5, logcache, accounts, anon, gesamt), the same as INFO in block 6 and as `profile` array in the JSON.
- **Config template bilingual.** `ns_quickcheck.conf.example` carries a German and an English comment line before every parameter; `release.sh` checks it. `AAA_SHARED_OK`, `AAA_SHARED_USERS` and `ANON_ACCOUNTS` added to the template.
- `v18.4.md` frozen once it has run.
