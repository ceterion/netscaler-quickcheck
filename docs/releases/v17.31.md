# netscaler-quickcheck v17.31 (2026-10-27)

Trusted list and report footer. Rules stand 2026-10-23 unchanged. Everything else as in `v17.30.md`.

## New in v17.31

- **Trusted list** `ns_quickcheck.trusted_ips` next to the script (or `--trusted <path>`): `address_or_network ; until ; remark`. For addresses whose attack-like behaviour is wanted: vulnerability scanners, penetration testers within their engagement window, monitoring, partner gateways. Entries expire with the `until` date; an address that is also in the block list raises a WARN and the block list wins.
- **Effect:** in the management, SSH and account-failure checks a trusted address counts as internal; attempt findings (probing, dropper requests, spraying, brute force, sleepers) drop the address and it appears once, with everything it did in the window, as `[TRUST]` in blue without effect on the verdict (`TRUST_LEVEL=yellow` turns that into yellow). Effect findings (injection line, webshell answering 200, login after a failure series, active connection) stay red with a note. A trusted address that the cumulative address list previously held as an attacker gets a one-time yellow line.
- Address lists carry trusted addresses under `trusted_<category>`; the import command excludes them. `trusted_seen=` in the result line, list `trust` in the JSON.
- **Footer** in report and anonymized copies: tool, version, rules stand, licence, publisher, source; `FOOTER=0` in the config switches it off. `source_url` in the JSON.
- New fixture `trusted`; `--trusted` option; template `ns_quickcheck.trusted_ips.example`.

## Update

Replace `ns_quickcheck.sh` in `/var/nssnapshot/`; the rules file is unchanged. Optional: `ns_quickcheck.trusted_ips`, `TRUST_LEVEL` and `FOOTER` in `ns_quickcheck.conf`.
