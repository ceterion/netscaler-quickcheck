# netscaler-quickcheck v18.2 (2026-11-05)

Status: gelaufen (Betreiber-Gateway 2026-11-05, Script 392fb509...)

Follow-up to v18.1 from the customer runs of 2026-11-05. Rules stand 2026-11-05d unchanged.

## New in v18.2

- **CSP reports, baseline and scanner handling.** An INFO counts the CSP reports of the logon page without payload (browser extensions, foreign scripts) with the five most frequent blocked sources, so a scan stands out from the baseline. The scanner finding can be yellow instead of red with `CSP_SCAN_LEVEL=yellow` for operators with regular vulnerability scans (there is no source address to trust). Its "to do" now carries the firewall search: local time window computed from the GMT report times, the gateway VIPs from the configuration, a ready `grep` for the access-log cross-check, and the rule "abuse report only after the pentest question".
- **Catalog text** of the CSP source line: the reports do not reach the web server; address via firewall logs or a responder policy on the report-uri path (README 15).
- **Version rule.** Every change to the script, the rules file or a catalog gets a new version number. Release notes of a version that ran on an appliance or was pushed carry `Status: gelaufen` or `Status: gepusht` and are frozen; `release.sh` refuses to build such a version with different files.
